# Domain docs

## Layout and reading rules

Single-context: root CONTEXT.md and docs/adr/.

Before exploring, read CONTEXT.md and ADRs relevant to the work.
If absent, proceed silently. Domain-modeling creates them lazily
when terminology or decisions are resolved.

## Vocabulary

Use domain terms defined in CONTEXT.md.
Note genuine glossary gaps for domain-modeling.

## Decisions

Explicitly flag proposals that contradict an existing ADR,
citing the ADR and explaining why it merits reconsideration.
